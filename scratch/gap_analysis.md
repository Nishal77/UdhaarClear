FINAL SECTION: Flagged Issues
* **Critical Security Risk — Broken Middleware:** [Needs verification] The root middleware file is named [proxy.ts](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/proxy.ts) instead of `middleware.ts`. Next.js ignores `proxy.ts`, which means the Supabase session validation, onboarding checks, and CA referral cookie capturing are completely bypassed.
* **Pricing Plan & Limit Mismatch:** [Needs verification] The pricing rates and limits in [plans.ts](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/lib/plans.ts) (Starter: ₹799/mo, 25 customers; Growth: ₹1999/mo, 100 customers) do not match the PRD's specifications (Starter: ₹399/mo, 15 customers; Pro: ₹999/mo, 200 customers).
* **Mocked Dashboard Admin Queue:** [Needs verification] In [IncomingPayments.tsx](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/components/dashboard/IncomingPayments.tsx#L89-L99), the "Verify" and "Report dispute" buttons for self-reported UTR receipts are fake UI methods that display mock Toast messages and filter arrays in local state, making no actual database updates.
* **Mocked Debtor Profiles:** [Needs verification] The payment habits statistics displayed on the customer dashboard list are hardcoded via modulo calculations on string character codes (e.g. `c.name.charCodeAt(0) % 2 === 0`), completely mimicking real payment patterns.
* **Mocked CA Registration Verify:** [Needs verification] The backend directory lookup in [icai-verification.ts](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/lib/ca/icai-verification.ts#L26) always resolves to a mock `MANUAL_REVIEW` status, meaning no live membership checks occur.
* **WABA OTP Template Approval:** [Needs verification] In [templates.ts](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/lib/whatsapp/templates.ts#L14), the `ca_partner_otp` template name is marked as pending review; OTP verification is blocked until confirmed live with the Meta WhatsApp Manager dashboard.
* **RazorpayX Live Sandbox Payouts:** [Needs verification] The RazorpayX direct API endpoints configured in [payouts.ts](file:///Users/nishalpoojary/Projects/Saas/UdhaarClear/lib/ca/payouts.ts#L14) have not been verified against a live sandbox account, risking payout failures or format conflicts.
* **Ambiguous Tally Integration Requirements:** [Guessing] The PRD is ambiguous regarding whether "Tally ERP — import invoices directly" means a live desktop API integration or simply uploading report CSV/Excel exports (which is what is built).
* **Missing Late Fee Feature:** [Needs verification] The PRD references "late fee policy if set" under Phase 2 reminders, but no model attributes exist on the database `Invoice` table to configure or record a late fee rate.

The single biggest risk to shipping is that the application's authentication, route protection, and CA referral cookie capture middleware is completely bypassed because the middleware file is misnamed `proxy.ts` instead of `middleware.ts` in the root folder.
